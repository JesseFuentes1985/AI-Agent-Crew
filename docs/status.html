Resolved 2026-08-15 RAG / ChromaDB
⚠️ Issue
RAG database completely offline. ChromaDB 1.1.1 crashed on every import with a ModuleNotFoundError for pydantic.v1. The daily sync cron was running but nothing was being indexed. 166 vectors sitting in the DB, unreachable.
🔍 Root Cause
ChromaDB 1.1.1 uses from pydantic.v1 import BaseSettings — the Pydantic v1 compatibility shim. Python 3.14 removed support for that shim entirely. The moment you tried to import chromadb, Python threw and the whole RAG stack went down with it.
🔧 Fix
Upgraded ChromaDB from 1.1.1 → 1.5.9 in the .venv (Python 3.14) environment. Version 1.5.9 uses Pydantic v2 natively — no compat shim. Zero data loss: all 166 vectors confirmed intact after upgrade.
.venv/bin/pip install --upgrade chromadb
✅ How to Test
Run this in terminal — if it prints the vector count, RAG is healthy:
cd ~/.openclaw/workspace-main
.venv/bin/python -c "import chromadb; c = chromadb.PersistentClient(path='~/.openclaw/rag/db'); print(c.get_collection('knowledge').count())" ✓ Expected output: 166
Resolved 2026-08-14 GitHub CLI / gh auth
⚠️ Issue
GitHub CLI authenticated but gh commands that touch org data failed with "missing required scope: read:org". Could not push to repos or access org-level info.
🔍 Root Cause
Token was piped in via echo TOKEN | gh auth login --with-token. That method only grants the scopes baked into the token at creation time. The token was missing read:org.
🔧 Fix
Re-authenticated via the interactive device OAuth flow instead of token pipe. Selected all required scopes during the browser flow.
gh auth login
Scopes granted: repo, read:org, gist. Then wired gh into git HTTPS with gh auth setup-git.
✅ How to Test
gh auth status ✓ Expected: account JesseFuentes1985, scopes include repo, read:org, gist
