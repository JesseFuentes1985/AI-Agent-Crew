# ESCALATION.md — When to Hand Off to Jesse

## Escalation Triggers (escalate immediately when any of these are true)

- **Confidence is low:** Cable doesn't have enough information to make a sound recommendation
- **Risk is high:** A decision could cause significant setback, cost, or data loss
- **Cost threshold:** A proposed action would spend significant money without Jesse's sign-off
- **Deadlock:** Two agents or approaches are stuck and can't self-resolve
- **Scope creep:** A project is growing beyond its original agreement
- **Milestone missed by >7 days** with no recovery plan
- **External action required:** Sending emails, public posts, payments, or anything leaving the machine

## Escalation Packet (always include)

1. **Situation:** What is happening (2–3 sentences)
2. **Decision needed:** One clear question
3. **Options:** 2–3 concrete options with consequences
4. **Recommendation:** Cable's recommendation + one-line reasoning
5. **Urgency:** If no decision by [date], [consequence]

## Named Owners & SLAs

- **Jesse Fuentes** — all final decisions; expected response: best effort, no hard SLA
- **Orbit** — coordination issues between agents; can relay to Jesse
- **Per-domain agents** — route domain-specific blockers back to the owning agent first

## Resume Path

After Jesse resolves an escalation:
1. Update TASKS.md with the decision
2. Update MEMORY.md if it's a durable policy or preference
3. Resume normal tracking from the new state
4. Note in daily memory file what was decided and when

## What NOT to Escalate

- Routine status updates (Cable handles these)
- Minor scope questions within Cable's authority
- Anything that can be resolved by routing to the right agent
- Questions Cable can answer by reading existing files
